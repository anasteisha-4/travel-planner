# Triply Analytics Event Taxonomy

Updated: 2026-05-13

Purpose: document frontend events stored through Analytics Service `/api/v1/events`.
The taxonomy supports the diploma demo funnel and the future `hybrid-ranker-v2`
feedback loop.

## Contract Version

- Contract version: `2026-05-13`.
- Default event schema version: `event_version=1`.
- New clients send `event_id`, `event_version`, `occurred_at`, `client_meta.platform`,
  `client_meta.app_version`, `client_meta.path`, and `client_meta.referrer`.
- Analytics Service accepts unknown event names in soft mode, stores them, and
  returns contract warnings so old/new clients do not break ingestion.
- Retry deduplication is based on `event_id`; duplicate `event_id` rows are skipped.

## Shared Envelope

Every event is sent inside a batch item:

| Field | Required | Notes |
| --- | --- | --- |
| `event_id` | recommended | UUID generated by the client. Used for retry deduplication. |
| `session_id` | yes | UUID generated in `sessionStorage`; does not identify a person by itself. |
| `event_type` | yes | One of the documented event names below. |
| `event_version` | recommended | Integer schema version. Current default is `1`. |
| `entity_type` | no | Main object type: `destination`, `trip`, `itinerary`, `model`, `profile`, `user`, or `experiment`. |
| `entity_id` | no | Destination id, trip id, itinerary id, model version, or other join key when available. |
| `context` | no | Event-specific JSON fields. |
| `client_meta` | no | Device/app metadata. |
| `occurred_at` | no | Client timestamp; server `created_at` is used when absent. |

Authenticated requests are linked to `user_id` server-side from the JWT. Anonymous
or unauthenticated events keep only `session_id`.

## Event Classes, Owners, And Retention

| Class | Owners | Consumers | Examples | Retention |
| --- | --- | --- | --- | --- |
| `product` | frontend + product analytics | funnel dashboards, roadmap decisions | recommendation, trip, itinerary, profile events | 24 months |
| `ml_quality` | ML service + analytics | retraining datasets, offline eval, model registry reports | ranker/budget/itinerary quality snapshots | 24 months or until retraining snapshot expires |
| `operational` | backend/frontend engineering | incident debugging, latency/error dashboards | failed request, slow API, service worker error | 90 days |
| `experiment` | product + ML | A/B reports and guardrails | `experiment_exposed`, assignment metadata | 24 months |
| `admin_audit` | engineering | flag/experiment change audit | flag changed, experiment paused | 36 months |

## Privacy Classes

| Class | Examples | Storage rule |
| --- | --- | --- |
| `safe_id` | `destination_id`, `trip_id`, `recommendation_id`, `model_version` | Allowed when needed for joins. |
| `coarse_numeric` | rank, count, duration days, people count, warning count | Allowed. Prefer buckets for sensitive values. |
| `sensitive_numeric` | exact budget, exact expense amount, actual trip total | Allowed only when required for product/ML metrics. |
| `forbidden` | email, token, password, OAuth id, notes, descriptions, free-text feedback | Never store in event context. |

## Privacy Notes

- Do not put email, login, access tokens, OAuth ids, free-text profile notes, or
  expense descriptions into `context`.
- Store destination/trip identifiers and coarse numeric values needed for model
  learning. For sensitive values, prefer booleans such as `has_budget` or bucketed
  values unless exact value is needed for a product metric.
- Free-text post-trip feedback is stored in the feedback table, not duplicated in
  event context.
- Analytics Service strips forbidden context/client_meta keys before storing an
  event. Forbidden key patterns include email, password, token, secret, OAuth id,
  notes/descriptions, and free text.

## Contract Evolution

- Additive optional fields may be added to an existing event version.
- New required fields need a new `event_version` or a new event name.
- Event renames should keep the old name accepted for at least one release cycle.
- Deprecated events should remain documented with a replacement event and removal date.
- ML datasets must record event contract version and date range used for a snapshot.

## Server-Side Normalization

- Known canonical event names are validated against required context fields.
- Missing required context fields do not reject the batch; they produce contract
  warnings and the event is still stored.
- Unknown event names are stored and reported via warnings.
- `entity_type` is normalized to known entity types. When omitted, Analytics
  Service infers destination/trip/itinerary/profile where possible from context.
- `client_meta.server` is added with service name, service version, environment,
  request id, contract version, and default event version.

## Funnel Reconstruction

Minimum path from recommendation to trip:

1. `recommendation_impression` with `recommendation_id`, `destination_id`, `rank`.
2. `recommendation_clicked` or `destination_detail_opened` for the same destination.
3. `validation_viewed` and/or `budget_prediction_viewed`.
4. `trip_created` with `source=recommendation`, `recommendation_id`, and `trip_id`.
5. `trip_opened`, `itinerary_generated`, `expense_added`, and
   `post_trip_feedback_submitted` for downstream engagement and quality.
